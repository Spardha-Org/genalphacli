name: brainstorm-question-style
description: User prefers brainstorm questions to be thorough and well-researched before asking, not rapid-fire
type: feedback
---

When brainstorming, do thorough research FIRST, then ask well-informed questions with full context. Don't ask questions before research is complete — the answers change based on what's technically possible.

**Why:** The MCP brainstorm went poorly because questions were asked before the research agent finished, leading to options that didn't account for technical realities (e.g., from_openapi() needs an actual OpenAPI spec, not graph.json). This forced backtracking and confused the flow.

**How to apply:** Complete ALL research agents before starting the collaborative dialogue. Present findings to the user first, THEN ask questions informed by what's actually feasible.
