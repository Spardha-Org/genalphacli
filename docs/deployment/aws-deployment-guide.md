## Key Design Decisions

### Why 2 EC2 instead of 1
- Temporal + its PostgreSQL uses ~700MB RAM
- Backend services use ~400MB RAM
- Single t3.micro (1GB) can't fit both
- t3.small (2GB) is free tier in ap-south-1

### Why RDS instead of Docker PostgreSQL for app data
- Managed backups (when enabled)
- Free tier includes db.t3.micro
- Survives EC2 instance replacement
- Temporal gets its own PostgreSQL in Docker (doesn't need persistence guarantees)

### Why Docker service names instead of localhost
- Each Docker container has its own network namespace
- `localhost` inside container = that container, not the host
- Docker Compose creates a DNS network: `core`, `tps`, `worker` resolve to container IPs
- Exception: nginx uses `network_mode: host` to bind port 80 on the host

### Secret Sync Rules (CRITICAL)

These secrets MUST have the same value across services:

```
TPS_SECRET:
  CORE_TPS__SECRET     (Core reads)
  TPS_TPS_SECRET       (TPS reads)
  TPS_SECRET           (Worker reads)
  → All must be the SAME value

WORKER_SECRET:
  CORE_WORKER__SECRET  (Core reads)
  WORKER_SECRET        (Worker reads)
  → Both must be the SAME value
```

If they don't match:
- TPS returns "Invalid TPS secret" → App Store shows nothing
- Core returns 401 on /api/v1/internal/* → Worker can't update status

## Workarounds & Issues Encountered

### 1. t2.micro not free tier in ap-south-1
**Problem:** Terraform errored with "instance type not eligible for Free Tier"
**Fix:** Use `t3.small` (2GB RAM, free tier in ap-south-1)
**Command to check:** `aws ec2 describe-instance-types --filters "Name=free-tier-eligible,Values=true"`

### 2. Security group description with em-dash (—)
**Problem:** AWS rejects non-ASCII characters in SG descriptions
**Fix:** Replace `—` with `-` in all security group descriptions

### 3. RDS backup_retention_period > 0
**Problem:** "exceeds maximum available to free tier customers"
**Fix:** Set `backup_retention_period = 0` for free trial accounts

### 4. Git clone fails on EC2 (private repo)
**Problem:** User data script can't clone private repo — no GitHub auth
**Fix:** Made repo public. Alternative: use deploy key or PAT

### 5. Temporal crash-loops on startup
**Problem:** `Unable to create dynamic config client: stat config/dynamicconfig/development-sql.yaml: no such file or directory`
**Fix:** Remove `DYNAMIC_CONFIG_FILE_PATH` env var from docker-compose.infra.yml. Set `SKIP_DYNAMIC_CONFIG_SETUP=true` instead.

### 6. Core can't reach Temporal (timeout)
**Problem:** Core used public IP `13.232.30.91:7233` to reach Temporal. Security group allowed 7233 from `sg-backend` but SG source rules only work with private IPs.
**Fix:**
1. Changed TEMPORAL_ADDRESS to private IP `10.0.1.180:7233`
2. Added VPC CIDR `10.0.0.0/16` to infra SG for port 7233
**Key lesson:** Inter-EC2 communication within VPC must use private IPs for security group source rules to work.

### 7. Core can't reach TPS (httpx.ConnectError)
**Problem:** Core sends HTTP to `http://localhost:8001` but inside Docker, localhost = the container itself
**Fix:** Use Docker service names: `http://tps:8001`, `http://core:8000`
**Key lesson:** Docker Compose creates a DNS network. Services reference each other by service name, not localhost.

### 8. Worker can't reach Core (401 Unauthorized)
**Problem:** Worker sends `X-Worker-Secret: abc` but Core expects `X-Worker-Secret: xyz`
**Root cause:** Secrets were randomly generated separately in the .env — `CORE_WORKER__SECRET` ≠ `WORKER_SECRET`
**Fix:** Manually synced all related secrets to the same value
**Key lesson:** The deploy workflow must use a SINGLE secret value for all related env vars.

### 9. TPS "Invalid TPS secret"
**Problem:** Same as #8 but for TPS secret — `CORE_TPS__SECRET` ≠ `TPS_TPS_SECRET` ≠ `TPS_SECRET`
**Fix:** Synced all three to the same value

### 10. Fernet key invalid ("Incorrect padding")
**Problem:** `.env` had `TPS_FERNET_KEYS=placeholder-key` — not a real Fernet key
**Fix:** Generate proper key: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
**Key lesson:** Fernet keys must be exactly 32 url-safe base64-encoded bytes

### 11. Missing database tables ("relation core_users does not exist")
**Problem:** Alembic migrations never ran on production RDS
**Fix:** Run migrations inside the container:
```bash
sudo docker exec compose-core-1 bash -c 'PYTHONPATH=.:src uv run alembic -c services/core/alembic.ini upgrade head'
sudo docker exec compose-core-1 bash -c 'PYTHONPATH=.:src uv run alembic upgrade head'
```
**Key lesson:** Add migration step to deploy workflow or Docker entrypoint

### 12. README.md missing in Docker build
**Problem:** `hatchling` build requires README.md but Dockerfile didn't COPY it
**Fix:** Added `COPY pyproject.toml uv.lock README.md ./` to both Dockerfiles

### 13. Worker missing httpx dependency
**Problem:** Worker Dockerfile installed `--group worker` only, but worker imports httpx (from services group)
**Fix:** `RUN uv sync --frozen --no-dev --group worker --group services`
**Key lesson:** Worker activities import from both `genalphacli` (needs services deps) and `worker` packages

### 14. Docker compose restart doesn't reload env
**Problem:** `docker-compose restart` reuses existing container env vars
**Fix:** Must `docker-compose down` then `docker-compose up -d` to pick up .env changes

### 15. GitHub rejects workflow file push
**Problem:** `refusing to allow an OAuth App to create or update workflow without workflow scope`
**Fix:** `gh auth refresh -s workflow` to add the workflow scope to the token

### 16. GitHub secret name can't start with GITHUB_
**Problem:** `GITHUB_OAUTH_CLIENT_ID` rejected — reserved prefix
**Fix:** Renamed to `OAUTH_CLIENT_ID` and `OAUTH_CLIENT_SECRET`

## Deployment Pipeline (CI/CD)

On every push to `main`, GitHub Actions runs 3 parallel jobs:

### Job 1: deploy-frontend (Vercel)
```
checkout → install vercel CLI → vercel pull → vercel build --prod → vercel deploy --prebuilt --prod
```

### Job 2: deploy-backend (EC2 #1)
```
SSH into backend EC2 →
  write .env from 11 GitHub secrets →
  git pull →
  docker-compose down →
  docker-compose up -d --build
```

### Job 3: deploy-infra (EC2 #2)
```
SSH into infra EC2 →
  git pull →
  docker-compose pull →
  docker-compose up -d
```

## Manual Operations

### SSH into instances
```bash
ssh -i ~/.ssh/genalpha_deploy ec2-user@43.204.165.207  # Backend
ssh -i ~/.ssh/genalpha_deploy ec2-user@13.232.30.91    # Infra
```

### View logs
```bash
# On backend EC2
sudo docker logs compose-core-1 -f
sudo docker logs compose-tps-1 -f
sudo docker logs compose-worker-1 -f

# On infra EC2
sudo docker logs compose-temporal-1 -f
```

### Run migrations
```bash
# On backend EC2
sudo docker exec compose-core-1 bash -c 'PYTHONPATH=.:src uv run alembic -c services/core/alembic.ini upgrade head'
sudo docker exec compose-core-1 bash -c 'PYTHONPATH=.:src uv run alembic upgrade head'
```

### Restart services
```bash
# On backend EC2
sudo docker-compose -f /opt/genalpha/repo/infra/compose/docker-compose.backend.yml --env-file /opt/genalpha/.env down
sudo docker-compose -f /opt/genalpha/repo/infra/compose/docker-compose.backend.yml --env-file /opt/genalpha/.env up -d

# On infra EC2
sudo docker-compose -f /opt/genalpha/repo/infra/compose/docker-compose.infra.yml down
sudo docker-compose -f /opt/genalpha/repo/infra/compose/docker-compose.infra.yml up -d
```

### Create RDS databases (first time only)
```bash
export PGPASSWORD="<db-password>"
psql -h <rds-host> -p 5432 -U genalpha -d genalpha -c "CREATE DATABASE core"
psql -h <rds-host> -p 5432 -U genalpha -d genalpha -c "CREATE DATABASE tps"
```

### Generate a Fernet key
```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### Destroy all infrastructure
```bash
cd infra/terraform
terraform destroy -auto-approve
```
